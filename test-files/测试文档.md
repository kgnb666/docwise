# DocWise 测试文档：智能运维与可观测性实践

> 本文档为 DocWise 平台的功能测试语料，内容为虚构的运维实践场景，
> 用于验证：文档分块、混合检索、引用溯源、防幻觉、Markdown 渲染。

## 一、什么是可观测性

可观测性（Observability）是系统对外部问题的可回答程度，三大支柱为：
日志（Logs）、指标（Metrics）、链路追踪（Traces）。与"监控"不同，
可观测性强调**未知问题的探索能力**——监控回答"我知道它坏了"，
可观测性回答"我不知道会坏什么，但坏了能查出来"。

## 二、DocWise-X 协议规范（虚构示例）

DocWise-X 是本文档虚构的采集传输协议，仅用于测试：

- 传输端口：**9801**（TCP）
- 心跳间隔：**5 秒**，连续 **3 次**心跳超时判定节点离线
- 单帧最大负载：**64KB**，超过则分片，分片数上限 8
- 请求超时：**300ms**，超时后重试，最多 **2 次**
- 帧头魔数：`0xDW9F`，用于快速校验帧合法性

> 注意：以上参数在真实世界中不存在，仅用于测试模型"只依据资料回答、不编造"。

## 三、日志采集架构

LogAgent 是日志采集组件，运行在每个节点：

1. 读取本地日志文件，按行解析并打上节点标签；
2. 写入本地缓冲（默认 **64MB**，写满触发滚动）；
3. 批量上报：**每 500 条或 1 秒**触发一次发送（先到先发）；
4. 上报失败进入重试队列，重试间隔指数退避：1s → 2s → 4s；
5. 重试 **5 次**仍失败则落盘到 `failed/` 目录，等待人工补偿。

采样策略：默认全量采集；高流量时段可按 **10% 采样率**降级，
采样时保留请求关联 ID 以保证链路可追踪。

## 四、指标与告警规则

常用告警阈值（示例）：

| 指标 | 阈值 | 持续时间 | 级别 |
|---|---|---|---|
| CPU 使用率 | 85% | 5 分钟 | 警告 |
| 内存使用率 | 90% | 5 分钟 | 警告 |
| 错误率（5xx 占比） | 1% | 3 分钟 | 严重 |
| P99 延迟 | 800ms | 5 分钟 | 严重 |

告警去重：同一规则同一目标 30 分钟内只通知一次；静默窗口可通过配置关闭。

## 五、链路追踪与采样

链路追踪用 Trace ID 串联一次请求的所有跨度，格式：`dw-` 前缀 + 16 位十六进制，
如 `dw-9f3a1c8e2b47d605`。跨度（Span）记录：开始时间、耗时、状态、父子关系。

追踪采样策略：头部采样（按 Trace ID 哈希）与尾部采样（按结果）两种，
默认 **固定比率 5%**；出现错误时强制全采（错误追踪 100% 保留）。

## 六、部署与回滚

发布采用**蓝绿部署**：新旧两套环境并存，流量一键切换，切换失败 10 秒内自动回滚。
金丝雀发布：先放量 **5%** 流量观察 30 分钟，指标平稳后逐步放量 25% → 50% → 100%。
回滚触发条件：错误率超过 2% 或 P99 延迟超过 1 秒，自动回滚并告警。

```yaml

  buffer_size_mb: 64
  batch_size: 500
  flush_interval_sec: 1
  retry:
    max_attempts: 5

  sampling_rate: 0.1

protocol:
  name: docwise-x
  port: 9801
  heartbeat_sec: 5
  frame_max_kb: 64
  timeout_ms: 300
```

## 八、常见问题速查

- 日志丢失怎么办：检查 LogAgent 缓冲是否写满、重试队列是否积压、`failed/` 目录是否有补偿文件；
- 告警风暴怎么避免：启用告警去重、配置静默窗口、按级别分级通知；
- 追踪数据量太大：降低固定采样率，或改用头部采样按用户维度抽样；
- 回滚失败怎么办：蓝绿环境保留 24 小时，直接切换流量并保留现场用于排查。
