# 系统设计入门

## 设计流程

四步法：明确需求（功能+非功能：QPS/延迟/数据量）→ 估算规模 →
设计架构（分层/模块/数据流）→ 深入细节（存储选型/缓存/一致性）。
先画系统骨架再逐层展开，边讲边写白板。

## 常用组件与手段

- 缓存：抗热点读，Redis；注意穿透/击穿/雪崩与一致性；
- 消息队列：削峰填谷、解耦、异步化；
- 限流：令牌桶/漏桶/滑动窗口，网关层统一做；
- 降级与熔断：依赖故障时走降级逻辑，熔断器（Hystrix/Sentinel）快速失败；
- 幂等：重复请求只生效一次（唯一键+状态机），支付场景必须；
- 分库分表：水平拆分按 key 路由，垂直拆分按业务域；跨分片查询代价大。

## 经典题目套路

- 短链系统：发号器（雪花算法/DB 自增）+ 62 进制编码 + 缓存映射；
- 秒杀：前端限流 → 网关限流 → Redis 预扣减库存 → MQ 异步落单 → 对账；
- 消息系统：分区+副本+消费组+幂等+顺序保证；
- 关注/Feed 流：推模式（写扩散）、拉模式（读扩散）、推拉结合。

## 估算示例

单机 QPS 量级：Nginx 数万、应用服务器数千、MySQL 数千（简单查询）、
Redis 十万级。缓存命中率 90%+ 时，10 万 QPS 的读场景可用几十台实例扛住。
