# 示例文档：RAG 技术笔记

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把「检索」和「生成」结合起来的架构。
它的核心思想是：在让大语言模型生成回答之前，先从外部知识库中检索出与问题相关的资料片段，
把这些片段作为上下文一起交给模型，从而让模型基于真实资料回答，而不是凭记忆编造。

## RAG 的典型流程

一个标准的 RAG 流程包含五个环节：

1. 文档解析：读取 PDF、Word、Markdown 等格式的原始文档，提取纯文本；
2. 文本分块：把长文本切分成语义完整的小块（chunk），方便后续检索；
3. 向量化：用嵌入模型（Embedding Model）把每个文本块转换成向量；
4. 检索：把用户问题也向量化，然后在向量库中找出最相似的若干文本块；
5. 生成：把检索到的文本块作为参考资料，连同问题一起交给 LLM 生成带引用的回答。

## 为什么需要混合检索

纯向量检索（语义检索）擅长处理"意思相近但用词不同"的查询，
但遇到精确匹配的场景（型号、代码、人名、专有名词）容易失手；
BM25 这类关键词检索正好相反。混合检索把两者的得分归一化后加权融合，
能同时兼顾语义和精确匹配，是工业界的主流做法。

## 如何评测 RAG 系统

评测是 RAG 系统能否上线的前提。常用指标包括：

- 命中率 / 召回率：正确答案是否出现在检索到的片段里；
- 忠实度：模型回答是否严格基于检索到的资料，有没有编造；
- 答案相关性：回答与问题的相关程度。

实践上需要自建测试集（问题 + 标准答案 + 期望来源），
然后对比不同配置（如是否加 Rerank、分块大小）下的指标变化，用数据驱动优化。
