# 分布式系统基础

## CAP 与 BASE

CAP：一致性（C）、可用性（A）、分区容错（P）三者最多满足其二；
网络分区必然发生，所以实际是 CP 或 AP 的取舍。
BASE：基本可用、软状态、最终一致——互联网系统的现实选择（放弃强一致换可用性）。

## 一致性协议

- 两阶段提交（2PC）：准备+提交两阶段，协调者单点、阻塞问题；
- Paxos/Raft：多数派投票，容忍少数节点故障；Raft 更易理解（Leader 选举+日志复制）；
- 最终一致：异步复制 + 对账补偿，牺牲实时性换取可用性。

## 分布式事务

- 本地消息表：业务和消息同库事务，消息异步投递；
- 事务消息（RocketMQ）：半消息+回查；
- TCC：Try-Confirm-Cancel 三段式，业务侵入大但控制力强；
- Saga：长事务拆子事务+补偿，适合跨系统业务流程。

## 负载均衡与一致性哈希

Nginx/LVS/注册中心（Nacos/Consul）做负载均衡：轮询、加权、最小连接、一致性哈希。
一致性哈希解决"节点增减导致大量缓存失效"：虚拟节点缓解数据倾斜。
服务发现：注册中心维护服务列表，客户端拉取+本地缓存+健康检查。
