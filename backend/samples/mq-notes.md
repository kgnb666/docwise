# 消息队列基础

## 为什么用 MQ

三大作用：异步（用户请求先返回，耗时操作后置）、削峰（突发流量排队消化）、
解耦（上下游互不感知，各自演进）。代价：引入延迟、增加系统复杂度、
消息可能丢失/重复（需要幂等）。

## 核心概念

生产者、消费者、Broker（服务端）、Topic（主题）、Partition（分区）、
Consumer Group（消费组：组内竞争、组间广播）。
偏移量（Offset）：消费者记录读到哪，可回溯重放。

## 消息可靠性

- 不丢失：生产者 ack、Broker 落盘+副本、消费者手动提交（处理完再提交）；
- 不重复：消费方幂等（唯一 ID 去重、状态机）；
- 不乱序：单分区内有序，顺序消息需保证同一 key 进同一分区。
至少一次（At-least-once）语义下，幂等是必须的。

## Kafka vs RabbitMQ

Kafka：高吞吐（顺序写盘+零拷贝）、日志/流处理场景、分区模型；
RabbitMQ：功能全（延迟队列/死信/优先级）、路由灵活，适合业务消息。
选型：大数据量选 Kafka，复杂路由/低延迟业务选 RabbitMQ。
