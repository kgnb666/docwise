# 演示脚本：3 分钟 Demo（面试/简历附件用）

> 目标：讲清楚「这是什么 → 怎么用 → 为什么牛」。控制在 3 分钟内，
> 先演示再讲原理，用"刚才那个画面"佐证每一个技术点。

## 0-30s：开场（30 秒电梯演讲）

> "这是我独立做的 DocWise——一个带评测体系的 RAG + Agent 知识库问答平台。
> 你可以上传任意文档，它能把文档变成可对话、可溯源、能执行任务的 AI 助手。
> 我重点想展示三件事：全链路 RAG、可量化的评测、Agent 工具调用。"

## 30s-1m10s：上传 + 提问（演示核心链路）

1. 打开页面 → 左侧点「上传文档」，传 `backend/samples/rag-notes.md` 和 `docker-notes.md`
2. 右侧提问：「什么是 RAG？」→ 回答流式出现（打字机效果）
3. **指屏幕**：「注意回答下方有引用出处——点击能看到来源片段，这是 RAG 和普通聊天最大的区别：**每个回答都有据可查**」
4. 再问：「docker compose 有什么用处？」（展示跨文档检索）

## 1m10s-1m50s：追问改写（亮点 1）

1. 紧接着问：「**它** 和虚拟机有什么区别？」
2. 回答上方出现绿色提示：「🔄 已将追问改写为『docker compose 和虚拟机有什么区别』用于检索」
3. 讲解：「这就是追问改写——用户说『它』，系统自动补全上文再检索，不然『它』根本查不到任何东西」

## 1m50s-2m30s：Agent 工具调用（亮点 2）

1. 提问：「用计算器算一下 (1+2)*3，再查一下维基百科上『检索增强生成』是什么」
2. 回答里出现黄色芯片：「🔧 调用了 calculator」「🔧 调用了 wiki_search」
3. 讲解：「模型判断需要外部能力时，会通过 Function Calling 调用我注册的工具，结果回填后再组织答案——知识库答不了的，它能联网去找。每轮调用有次数上限，防死循环」

## 2m30s-3m00s：评测数据收尾（亮点 3，最重要的记忆点）

1. 打开 `docs/eval/offline_report.json` 或终端跑：
   ```
   cd backend && python scripts/run_eval.py
   ```
2. 展示四档对比（纯向量 96.9% / 混合 100% / 混合+OverlapRerank 100% / 混合+bge-reranker API 100%）
3. 讲解：「很多人做 RAG 只说『效果不错』，我做了评测体系：测试集 + 命中率 + LLM 判分。**每一次优化都有数字证明**——top-1 严格模式下，纯向量 96.9%，混合检索靠 BM25 关键词纠偏到 100%。」

## 结尾（10 秒）

> "项目有 54 个单元测试、CI、Docker 部署配置，代码都在 GitHub 上（放链接）。谢谢！"
